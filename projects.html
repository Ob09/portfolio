Earthquake Magnitude Prediction System

Master's Thesis Project | End-to-End ML Pipeline with Explainability & Deployment

Project Overview

This project builds a full data-science pipeline to estimate earthquake magnitude from historical seismic records, to support risk assessment and disaster-preparedness decision-making (not “predicting” exact future earthquakes, but modelling magnitude based on observed event features).

Data + Problem Setup

  • Used USGS + Associated Seismic Database records covering earthquake activity in the United States and nearby Canadian provinces (1800–1984).
  • After cleaning, the modelling dataset contained 44,231 earthquake records and 14 features, combining:
    • Temporal: YEAR, MONTH, DAY, HOUR, MINUTE
    • Spatial: LATITUDE, LONGITUDE, CITY_LAT, CITY_LON, STATE, COUNTRY
    • Geophysical: EQ_DEPTH, EPIDIST, MMI (with magnitude as target)

Data Cleaning + Preprocessing (Reproducible Pipeline)

  • Performed structured cleaning: handling missing records/columns, removing duplicates, standardising date/time formats, and ensuring correct data types.
  • Applied preprocessing for ML-readiness: 80/20 train-test split, standardisation for numeric features, and one-hot encoding for categorical variables.

Feature Engineering + Selection

  • Engineered features to better represent physical relationships and reduce skew:
    • DIST_TO_CITY: distance from epicentre to nearest city (spatial risk proxy)
    • LOG_EQ_DEPTH and LOG_EPIDIST: log transforms to stabilise heavy right-skew and reduce outlier dominance
    • Event time categorisation to capture potential diurnal patterns.
  • Used Recursive Feature Elimination (RFE) with Random Forest to keep the most informative predictors while reducing redundancy/multicollinearity impact.

Model Benchmarking + Tuning

  • Trained and compared a range of regression models: Linear/Ridge/Lasso, SVR, MLP, Random Forest, XGBoost, and also trialled Symbolic Regression (gplearn) to explore interpretability trade-offs.
  • Selected XGBoost as the final model after hyperparameter tuning (RandomizedSearchCV, 5-fold CV). Best configuration included 104 trees, max_depth 14, learning_rate 0.195, subsample 0.993, colsample_bytree 0.636.

Reliability check: 5-fold cross-validation showed stable error (RMSE ranged 0.2566–0.2688). Diagnostic plots (Actual vs Predicted, residual distribution) showed errors centred near zero, supporting low bias and good fit.

Explainability (Trust + Transparency)

  • Added model interpretability using:
    • SHAP (global): strongest drivers included LOG_EPIDIST, LONGITUDE, MMI, LATITUDE; temporal features had smaller but consistent influence.
    • LIME (local): provided per-event reasoning, showing which conditions increased/decreased a specific prediction (useful for stakeholders).

Deployment (Usable Product)

  • Deployed the tuned model as a Flask REST API, tested via Postman, returning magnitude predictions as JSON.
  • Built an interactive Streamlit dashboard where users input earthquake parameters and get: real-time predictions + SHAP/LIME explanations + evaluation visuals (Actual vs Predicted, residuals, fold-wise RMSE).

Key Outcomes + Limitations

  • Outcome: a complete, interpretable ML system demonstrating how engineered spatio-temporal + geophysical variables can accurately estimate magnitude with strong generalisation.
  • Limitations noted: dataset is region-specific (US/nearby regions), and models are decision-support tools (not deterministic “earthquake forecasting”); ensemble methods can be more computationally expensive than linear baselines.
