Financial Market Data Pipeline

An end-to-end system that automatically fetches stock market data, processes it through Bronze/Silver/Gold layers, and serves it on a live public dashboard.

DockerAirflowPySparkFastAPIDashClaude-assisted
View Full Case Study

The Business Problem

Investors and analysts need continuously fresh, clean market data with computed indicators to spot trends. Stitching that together by hand across dozens of tickers, every day, doesn't scale — and a broken pipeline that fails silently is worse than no pipeline at all.

My Approach

  • Designed a Medallion Architecture data lake: Bronze holds raw data exactly as pulled from Yahoo Finance, Silver removes nulls/duplicates, Gold computes business-ready indicators.
  • Used PySpark window functions to calculate moving averages, daily returns, volatility, and RSI — partitioned by stock symbol.
  • Orchestrated the pipeline with an Apache Airflow DAG: fetch → bronze_to_silver → silver_to_gold → notify_complete. If any stage fails, everything downstream stops.
  • Containerised all six services with Docker Compose for a reproducible local environment.
  • Automated daily refreshes with GitHub Actions (6am weekdays) — sidestepping IP rate-limiting I hit polling locally.
  • Served the Gold layer through FastAPI on Vercel and a Plotly Dash dashboard on Render, backed by Supabase.

A Challenge Worth Mentioning

Supabase caps queries at 1,000 rows — but the dataset has 15,000+. I wrote PostgreSQL functions that aggregate server-side instead of paginating client-side. A similar constraint on Vercel (no persistent process for Dash) was solved by splitting the stack: stateless FastAPI on Vercel, persistent Dash on Render.

Earthquake Magnitude Prediction

A full ML pipeline that estimates earthquake magnitude from historical seismic records, built for explainability, not just accuracy.

PythonXGBoostSHAPFlaskClaude-assisted
View Full Case Study

The Business Problem

Emergency planners and insurers need a reliable estimate of expected earthquake magnitude from historical seismic patterns — and a model no one can explain is a hard sell to non-technical stakeholders making high-stakes decisions.

My Approach

  • Engineered a modular ETL pipeline processing 44,000+ seismic records using Pandas and NumPy.
  • Trained and evaluated 8 supervised ML models (Random Forest, XGBoost, SVR, MLP, Ridge, Lasso), comparing RMSE, MAE and R².
  • Selected the final model via 5-fold cross-validation and hyperparameter tuning.
  • Deployed behind a Flask REST API with a Streamlit front end for real-time predictions.
  • Applied SHAP and LIME so every prediction comes with an explanation of which features drove it.
